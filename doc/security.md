# 安全模型

## 1. 威胁模型

局域网可信环境为主，但服务目录可能包含不可信内容（共享下载目录），
且监听地址可被局域网内其他人访问（默认 `0.0.0.0`）。主要防护：

- 路径穿越与目录逃逸；
- 符号链接逃逸；
- 可执行内容在服务源内以网页渲染（XSS/钓鱼）；
- 未授权访问（可选认证）；
- 隐藏文件意外暴露。

## 2. 路径安全（`safePath`）

所有 `path` 参数统一经 `safePath` 校验：

- 拒绝绝对路径、`..` 穿越、非法字符；
- 规范化后必须落在服务根目录内；
- 文件操作前再以 `filepath.Rel` 复核，防止 TOCTOU。

## 3. 符号链接

服务目录内的符号链接**只允许指向服务目录内**：

- `os.Stat` 解析后再次校验目标在根目录内；
- 指向外部的链接在列表/搜索/下载/缩略图/zip 中一律拒绝（404）。

## 4. 隐藏文件

- 默认隐藏 `.` 开头文件（`--hidden` 可开启）；
- 未开启时：列表、搜索、直链、缩略图、zip 全部一致拒绝——不存在
  "列表看不到但能猜路径下载"的旁路。

## 5. 内容类型与可执行内容

- 全局响应头 `X-Content-Type-Options: nosniff`（禁止 MIME 嗅探）；
- HTML/SVG/JS/XML 等可执行/可脚本扩展名强制 `attachment` 下载——
  即使攻击者能向共享目录写入文件，直链打开也只是下载，不会在
  FileServer 源内以 `text/html` 渲染执行脚本（配合 nosniff 双保险）；
- 预览仅对白名单类型开放（图片/视频/音频/PDF/文本/代码），
  文本/代码类型以纯文本方式展示（不执行）。
- **写入范围（有限放开）**：允许「新建空文件」「新建单层文件夹」「编辑文本文件」、
  **显式开启后的文件上传**，以及**仅登录会话可用的文件管理**（重命名 / 移动 / 复制 /
  删除到回收站 / 回收站恢复与清理）。
  - 新建空文件**扩展名不限**（`POST /api/create`，`kind:"file"`，0 字节）；这是相对
    「仅白名单文本」的放开，但**不扩大 XSS 面**：全局 `nosniff` 仍生效，且
    `.html/.js/.svg` 等可脚本扩展名在 `handleFile` 中仍被强制 `attachment`
    下载，不会在 FileServer 源内以 `text/html` 渲染执行；
  - 白名单扩展名文本可新建/编辑（`doc/api.md` 列出清单）；新建时若带初始内容
    则沿用原子写，非白名单扩展名忽略内容只建空文件；
  - 新建单层文件夹用 `os.Mkdir`（**不** `MkdirAll`，父目录必须已存在），
    不带路径分隔符、不递归；
  - `.html/.htm/.svg` 等可脚本化扩展名**不在**可编辑白名单内，只能作为空文件创建；
  - 命名校验跨平台统一、以服务端为准（`validEntryName`）：去首尾空白后非空、
    不得为 `.`/`..`、不含 `/ \` 与 NUL、不含控制字符、不含 Windows 非法字符
    `< > : " | ? *`、不以 `.` 开头（隐藏）、不以 `.`/空格结尾、非 Windows 保留
    设备名（`CON`/`NUL`/`COM1..9`/`LPT1..9`，含带扩展名形式）、UTF-8 ≤255 字节；
  - 只创建不覆盖：文件 `O_CREATE|O_EXCL`、目录 `os.Mkdir` 的 `EEXIST` 一律 409；
  - 可编辑大小上限 2 MiB（`--text-max-bytes` 可配），超限只可预览；
  - 写入走既有 `safePath` + `pathWithin` 穿越/符号链接防护，原子写（临时文件 +
    rename），失败不留半截文件；并发写入以版本标识（mtime+size）校验，冲突返回 409；
  - 只读目录（无写权限位）返回 403；
  - 直链下载行为不因可编辑而放宽：`.html/.js/.svg` 仍强制附件下载。
- **文件上传**（`POST /api/upload`，仅在 `--allow-upload` /
  `FILESERVER_ALLOW_UPLOAD=1` 时可用，**默认关闭**）：
  - 目标目录经 `safePath` 解析（拒绝 `..`、绝对路径、符号链接逃逸），再用
    `hiddenBlocked` 拒绝隐藏目录与 `.FileServer`；`dir` 不合法统一 `400`，
    不区分「不存在」与「越界」，避免目录探测。
  - 文件名保留中文与空格，但**禁止 `/ \` 与 NUL**（直接解析 multipart 原始
    `filename`，不依赖 `Part.FileName()` 的 basename 处理），不得为空、`.`、`..`、
    点开头（隐藏文件，无论 `--hidden`）、`.FileServer`（含大小写变体）、Windows
    保留设备名、Windows 非法字符、点/空格结尾，UTF-8 ≤255 字节。
  - 只创建/替换普通文件；目标是目录一律拒绝（`409`），绝不对目录执行删除/覆盖。
  - 每个文件先写目标目录内的 `.upload-*` 临时文件，单文件超过
    `--max-upload-mb`（默认 1024）立即 `413`；全部条目校验通过后才 `rename` 落位，
    任一步失败清理未落位临时文件，不留半截文件。POSIX 覆盖为原子 rename；
    Windows 上 `overwrite` 需先删除再改名（存在极小非原子窗口，已在 api.md 注明）。
  - `ask` / `rename` 在落位前检查目标存在性；本地其他进程在检查与 rename 之间
    抢占同名文件时仍可能被替换——与既有文本原子写相同的残余 TOCTOU 面，风险以
    「攻击者已具备服务目录写权限」为前提。
  - **鉴权沿用全站门禁**：认证启用时必须是有效会话（`Authorization: Bearer`），
    否则 `401`；认证默认关闭时上传端点也随全站敞开。因此「上传 + 不可信网络」
    必须同时启用认证，不能只靠上传开关。
  - 上传不改变直链内容类型策略：上传的 `.html/.js/.svg` 等仍被强制附件下载，
    不会在 FileServer 源内以网页渲染执行。

- **分片 / 断点续传 / 秒传 / 目录预创建**（`/api/upload/{chunk,status,complete,instant,mkdir}`）：
  - **仅登录会话可用**：认证关闭或未登录一律 `401`；认证关闭时前端回退为第 1 段的
    单请求上传，不调用这些接口。
  - 分片会话目录固定为 `.FileServer/uploads/<upload_id>/<index>`，`upload_id` 必须是
    64 位十六进制；`index`/`total`/`size` 有明确上界，分片请求体上限 64 MiB。
    合并前逐片检查存在性，缺片会删除残缺会话且不产生目标文件。
  - 合并写目标目录的 `.upload-*` 临时文件，大小与可选 SHA-256 校验通过后再原子 rename；
    失败清理临时文件。目标路径/文件名沿用 `safePath` + `hiddenBlocked` + `validUploadName`。
  - 内容索引 `.FileServer/blobs/<sha256 前两位>/<sha256>` 只接受规范化十六进制哈希；
    登记前服务端重新计算文件 SHA-256，不信任客户端上报值。秒传落位优先硬链接，
    跨设备回退复制；覆盖/删除只减少链接，硬链接计数降到 1（只剩索引）时由清理回收。
    回收采用保守策略：平台读不到链接计数时跳过，不误删；回收站/外部硬链接仍计入链接数，
    因此恢复或外部引用期间内容不会丢。
  - 残留分片与孤儿 blob 在启动时与每日清理中处理；分片会话保留 24 小时。
  - 已知边界：文件系统不支持硬链接（部分 FAT/exFAT）时秒传落位退化为复制，去重只在
    占用空间层面失效，不影响功能；SHA-256 冲突概率可忽略，但仍按「哈希即内容身份」处理。

- **文件管理**（重命名 / 移动 / 复制 / 删除到回收站，`POST /api/{rename,move,copy,delete}`
  与 `/api/trash*`）：
  - **仅登录会话可用**：即使 `--auth-mode none`，管理端点也返回 `401`；不存在匿名
    写文件/删文件。前端仅在 `/api/info` 的 `manage=true` 时显示选择、右键菜单与回收站入口。
  - 源路径经 `manageSource` 校验：拒绝 `..`、绝对路径、盘符、NUL、`.FileServer` 与
    隐藏项；父目录的最近已存在祖先必须是根内真实路径；最后一段是符号链接时其目标也
    必须在根内，越界链接一律 `400`。删除/移动符号链接时操作链接本身，不误删目标。
  - 目标目录经 `safePath` + `hiddenBlocked` 校验且必须可写；移动/复制到自身子目录、
    同一批次目标重名、单批超过 200 项一律 `400`。
  - 删除只移动到 `.FileServer/trash/<id>/<原相对路径>`，不物理删除；回收站条目 id
    必须是服务端生成格式，恢复/彻底删除前会解析真实路径并确认仍在回收站内。
  - 覆盖已有目标时先把旧目标改名到同目录隐藏备份，操作失败自动回滚；复制目录递归
    保留结构、权限位与 mtime，符号链接不跟随（逐项失败）。
  - 批量操作逐项返回 `{moved|copied|restored, failed}`；部分失败仍为 `200`，前端列出
    失败项与原因，不静默吞掉。
  - 服务端日志只记录操作类型、数量、结果、会话短 id 与来源 IP，不记录文件名或内容。

## 5.1 分享链接（公开访问）

- **能力凭据**：token 为 16 字节 `crypto/rand` 随机数（base32 26 字符），不可枚举、
  不含路径；每次公开请求重新查记录并校验状态，不缓存授权。
- **提取码**：只保存 `sha256(token + NUL + code)`；校验通过后写 30 分钟 `HttpOnly`
  cookie（`SameSite=Lax`、Path 限定到该分享），cookie 值是绑定 token 与签发时间的
  HMAC，改值或过期即失效，服务重启后重新输入。同一 IP 每分钟最多 10 次失败，第 10 次
  起返回 429；错误文案统一，不区分「不存在 / 错误」。
- **路径边界**：公开接口先由 token 解析分享根，再以分享根为 base 解析请求路径；
  拒绝 `..`、NUL、Windows 盘符与越界符号链接；`.FileServer` 与未开启 `--hidden` 时的
  点开头条目不列出、不下载、不打包。响应不返回真实磁盘路径。
- **响应面**：公开页与公开接口带 `X-Robots-Tag: noindex, nofollow` 与 `no-store`；
  下载强制 `Content-Disposition: attachment`；预览对文本/代码及可脚本扩展名统一输出
  `text/plain`，不会在服务源内渲染执行。
- **状态**：撤销 / 过期 / 超次在写响应头前返回 `403` 与明确 `code`；下载次数在锁内
  校验并落盘，并发请求不能突破上限；撤销/删除记录只影响链接，不动源文件。
- **管理**：`/api/share*` 在认证启用时要求登录会话；认证关闭时随全站敞开（与项目
  默认语义一致）。日志只记录 token 前 8 位、类型、有效期、下载上限、是否设置提取码
  与来源 IP，不记录文件路径、内容或提取码。

## 6. 认证（可选，默认关闭）

- 启动参数 `--auth-mode none|totp|password|password+totp`（默认 `none`，局域网敞开，
  行为与历史版本一致）；兼容用法 `--auth user:pass` 等价于 `password` 模式 + 预置口令。
- 首次启动且 `--auth-mode != none` 时，浏览器落地**引导页**：设置口令（≥ 8 位；
  `password`/`password+totp`）与绑定 TOTP（`totp` 必须绑定不可跳过；`password+totp`
  可跳过，跳过后退化为单因素并可随时补绑）。引导完成后自动转登录页。
- 登录支持「记住我」，但**服务端不再下发 cookie**：登录响应体返回明文 `token`，
  前端据勾选写入 `sessionStorage`（不勾，关标签/浏览器即失效）或 `localStorage`
  （勾选，持久）。服务端 token 有效期统一 **7 天**（`--token-days`，默认 7；勾/不勾一致），
  由客户端存储决定「是否还要重新输」。
- XHR 请求经 `Authorization: Bearer <token>` 鉴权；浏览器原生媒体请求
  （`<video>/<img>/<a download>`/HLS 分片）无法带头，改用绑定会话的**短票** `?t=`
  （`POST /api/auth/ticket` 签发，默认 5 分钟、**只对 GET 生效**、会话撤销即失效）。
  短票可出现在 URL；**token 本体绝不进入 URL/日志**。旧版 `fs_session` cookie 仅作
  只读兼容（不再下发）。
- 凭据只存服务端产物于 `.FileServer/auth.json`（0600，原子写）：
  - 口令：自研 Argon2id PHC 哈希（`m=64MiB, t=3, p=4`，标准库自研，RFC 9106 向量校验）；
  - TOTP 密钥：**明文存储**（无主密钥可加密，取 0600 文件 + 目录受控，等价于 SSH
    私钥的保护级别；如需更强保护应在磁盘加密层解决）；
  - 会话 token：只存 `sha256` 哈希 + 过期时间，永不落明文；列表页也不显示明文。
  - 短票：只存哈希，仅内存（重启即失效），不落盘。
- 恒定时间比较：口令走 Argon2 派生后 `subtle.ConstantTimeCompare`，TOTP 校验同理。
- TOTP 重放防护：**任何一次成功的 TOTP 校验（引导绑定或登录）都会把该时间步计入
  已用集合**；同一步内同码再次使用一律拒绝，且不早于已消费步的窗口内码失效。
  窗口语义固定为当前步 ±1 步可接受、±2 步拒绝（未用过的码），不在本轮改动。
- 引导提交的**原子性**：`POST /api/auth/setup` 先校验全部必需因素（口令强度、
  TOTP 验证码），全部通过才一次性持久化口令哈希 + TOTP 绑定 + 配置状态；任一失败
  返回 `400` 且不写入任何部分状态，避免「口令已存、TOTP 未绑」却显示配置完成的
  伪装双因素状态。
- 失败限速：按客户端 IP 阶梯锁定（连续 5 次失败 → 60s → 300s → 900s，到顶维持）。
  默认不信任代理头；`--trust-proxy` 时按 `X-Forwarded-For` **最左**一个作为客户端
  IP（方向写死，避免伪造右值绕过）。
- 认证响应不区分「用户不存在 / 口令错 / 验证码错」，统一 `访问凭据无效`；日志
  （含 `-v`）不打印口令/token/验证码，`/api/auth/*` 仅记录路径不记录查询串。
- 登录页/引导页响应带严格 CSP、`X-Content-Type-Options: nosniff`、
  `Referrer-Policy: no-referrer`、`Cache-Control: no-store`。

### 6.1 丢失验证器 / 口令的自救（命令行重置）

服务**未启动**时，用同一 `--dir`（默认 exe 所在目录）执行：

```bash
# 仅清除 TOTP 绑定，保留口令（丢失验证器时用）
FileServer --reset-totp

# 清除全部凭据与会话，重新进入引导（口令也忘了时用）
FileServer --reset-auth
```

> 安全提示：重置后**任何人都能重新引导绑定**（谁先设谁拥有）。请在**受信网络**
> 下操作，重置完成并重新配置前不要对外暴露端口。命令执行后进程直接退出，需重新
> 启动服务并在浏览器完成引导。

## 7. 其他

- 隐藏目录 `.FileServer` 不在列表中显示，且其内部文件不可通过 API 访问
  （`hiddenBlocked` 拦截）；
- zip 打包同样走 `safePath`/符号链接/隐藏校验；
- 服务端不执行用户提供的任何代码；ffmpeg 参数全部由服务端构造
  （文件名仅作为位置参数传入，不以 shell 执行——`exec.Command` 无 shell 注入面）；
- 下载文件名 `sanitizeFilename` 清洗（去路径分隔符/控制字符），
  Content-Disposition 正确编码中文。
