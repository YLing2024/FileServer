# 需求书：新建空文件 + 新建文件夹（2026-10-17）

> 来源：用户 2026-10-17 原话 ——
> 「fileserver新建文件夹都没做吗？」→「你做成这样，可以新建空文件和文件夹，然后对于txt文件是支持编辑的，懂我意思了吗？」
> 「什么叫明确不做，肯定要做啊」
>
> 结论：`doc/REQUIREMENTS-v2-auth-text-portable.md` §6「明确不做（本轮）」里的**建目录**一项作废；
> 本轮做「新建空文件」+「新建文件夹」，编辑能力维持现状（文本类可编辑）。
> 其余仍不做：**删除 / 重命名 / 移动 / 上传**（本次用户未要求）。

## 1. 现状与差距

| 能力 | 现状 | 差距 |
|---|---|---|
| 新建文件 | 只有「新建**文本**文件」：扩展名必须在 `editableExts` 白名单内，且强制带初始内容 | 不能建空文件、不能建任意扩展名的文件 |
| 新建文件夹 | **没有**（`doc/security.md` §5、README「明确不做」都写着不做） | 要建 |
| 编辑文件 | 白名单文本类可编辑（原子写 + mtime/size 版本校验防并发覆盖） | 保持不动 |

## 2. 目标（本轮）

1. **新建空文件**：在当前目录按给定文件名创建**空文件**（0 字节），扩展名**不再限制**。
   - 若扩展名落在文本白名单内且用户填了「初始内容」，则写入该内容（保留现有能力，属于超集）。
   - 若非白名单扩展名：忽略初始内容，只建空文件（前端应把该输入框隐藏/禁用）。
2. **新建文件夹**：在当前目录创建**单层**子目录（不递归、不带路径分隔符）。
3. **编辑维持现状**：文本白名单（含 `.txt`）仍可预览/编辑；非文本类只读（预览/下载）。
4. 现有「浏览即读 / 不外泄 / 有限写入」的安全模型**不得削弱**。

## 3. 接口

新增一个统一端点（前端切换过去）：

```
POST /api/create
Content-Type: application/json
{ "dir": "<当前目录相对路径>", "kind": "file" | "dir", "name": "<名称>", "content": "<可选，仅 file 且文本白名单时生效>" }
→ 200 {"ok": true, "kind": "file", "name": "notes.md", "path": "sub/notes.md"}
```

- **保留** `POST /api/text/new` 原行为（白名单 + 内容），作为兼容入口；两者共用同一套命名校验与写入内核。
- 状态码语义（沿用现有风格，文案中文）：
  - `400` 名称不合法 / 目标不是目录 / `kind` 非法；
  - `403` 路径被拒（穿越、符号链接逃逸、根外）、目录只读、隐藏名；
  - `409` 同名已存在（目录或文件）；
  - `405` 方法不对（沿用现有中间件行为）。
- 认证：与既有写接口一致，走同一中间件；不得新增免鉴权路径。
- 更新 `doc/api.md`（新增 `POST /api/create` 一节，含请求/响应/错误表）。

## 4. 命名校验（跨平台，后端为准）

于服务端统一实现 `validEntryName(name) string`（返回中文错误原因），**前端不得只靠 JS 校验**：

1. 去首尾空白后非空；`name` 必须等于 `strings.TrimSpace(name)`（杜绝前后空格带来的同名混淆）；
2. 不得为 `.` / `..`；不得含 `/`、`\`、NUL；不得含控制字符（`< 0x20`）；
3. 不得含 Windows 非法字符：`< > : " | ? *`；
4. 不得以 `.` 开头（沿用 `hiddenBlocked` 的隐藏文件约定）；
5. 不得以 `.` 或空格**结尾**（Windows 会静默截断，导致跨平台不一致）；
6. 不得为 Windows 保留设备名（大小写不敏感，且含带扩展名形式）：`CON PRN AUX NUL COM1..COM9 LPT1..LPT9`（如 `con`、`CON.txt` 一律拒）；
7. UTF-8 字节长度 ≤ 255；
8. 目标不得已存在（文件用 `O_CREATE|O_EXCL`；目录用 `os.Mkdir` 的 `EEXIST`）→ `409`。

> 说明：现有 `validNewTextName` 只做 1/2 的一部分，**新增规则要对 `POST /api/text/new` 同样生效**（保行为兼容但收紧非法名）。

## 5. 写入内核

- 路径：沿用 `safePath` + `pathWithin(s.cfg.root, target)` 双重校验，父目录必须 `os.Stat` 为目录；
- 只读目录（`isReadOnlyMode`，如 0o555）→ `403`；
- 文件：`os.OpenFile(target, O_CREATE|O_EXCL|O_WRONLY, 0o644)`；白名单 + 有内容时沿用现有原子写（临时文件 + rename）；
- 目录：`os.Mkdir(target, 0o755)`，**不** `MkdirAll`（父目录必须已存在，避免意外造出深路径）；
- 失败不留半截产物；不写 `.FileServer/` 之外的用户文件（缓存约定不变）。

## 6. 前端（`internal/server/web/`，无构建链，改完需重编 exe）

- 顶部 `#btnNewText` 改为通用「新建」入口（图标 + `title`/`aria-label` 改为「新建文件 / 文件夹」）；
- 现有「新建文本文件」弹窗改为**新建弹窗**：顶部两选一（**文件** / **文件夹**，默认文件）；
  - 「文件」：文件名（含扩展名）+ 初始内容（**仅当扩展名在文本白名单内才显示**，否则隐藏并给出灰字提示「该类型只创建空文件」）；
  - 「文件夹」：只有文件夹名，无内容框；
- 成功后：`toast('已创建 ' + name)`，退出搜索态并 `loadList(state.path)` 刷新；**停留当前目录**（不自动进入新文件夹）；
- 错误：后端返回的中文文案内联显示在弹窗内（沿用 `#nfError` 样式）；
- 名称为空或仅空白时禁用创建按钮；回车提交、Esc 关闭维持现状；
- 窄屏可用（沿用现有响应式弹窗），移动端按钮不隐藏。

## 8. 测试与验收（缺一不可）

**Go 单测**（`internal/server/`，新增 `create_test.go`，与现有 `text_test.go` 风格一致）：

- 成功：建空文件（非白名单扩展名，0 字节）、建 `.txt` 带初始内容、建文件夹；
- 拒绝矩阵：`../x`、`a/b`、`.hidden`、结尾点/空格、`con`、`CON.txt`、超长名（>255 字节）、含 `:`/`*`/控制字符、空名、纯空白、`kind: "symlink"`；
- 冲突：同名文件已存在 → `409`；同名目录已存在 → `409`；并发同时建同名目录 → 恰一个成功、另一个 `409`；
- 权限：只读目录（0o555）→ `403`；父目录不存在 → `400`；目标路径是文件当 `dir` 用 → `400`；
- 安全回归：`safePath` 穿越/符号链接逃逸用例复用现有测试思路，确认新端点不能写到根外；
- 兼容：`POST /api/text/new` 行为不变（白名单外仍 403、带内容仍写入）。

**构建**：`make check` 全绿（fmt-check + 三平台 vet + 三平台 build + `go test ./...`）。

**E2E**（Python + Playwright，`scripts/`）：新增一段流程 —— 建文件夹 → 进入 → 在文件夹内建空文件（非白名单扩展名，确认 0 字节）→ 建 `.txt` 并编辑保存 → 回上级确认条目存在。不改动现有 e2e 断言。
